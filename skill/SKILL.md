# FPGA 整数推理验证

先确定用户要实现、修复还是只读核查，以及允许写入的目录。复用已有正确实现，按本次任务选择下面的流程，不自动启动完整工具链或改变模型。

## 工作流程

1. **绑定对象。** 记录源码、约束、模型、输入、参考输出与位流的版本和哈希，固定样本及标签；不以 `latest/current` 名称作为证据身份。路径可迁移，内容身份必须重新核验。见 [验证流程](references/workflow.md)。
2. **定义数值合同。** 明确 dtype、layout、零点、累加位宽、重标定、舍入、饱和和输出含义。独立参考不调用被测实现的核心算术 helper。按 [整数合同与边界](references/integer_contract.md) 建立手算反例。
3. **比较完整结果。** 按预先声明的张量形状和索引核对，不只比较 winner；拒绝缺尾、重复、未知索引、非法整数与越界值。随包 `scripts/check.py compare` 可比较规范化 CSV，格式见 [工具说明](references/tools.md)。原始帧的 CRC、地址、会话与字节序仍需工程自己的解析器验证。
4. **验证协议语义。** 从合同独立构造访问矩阵，覆盖状态、权限、地址、长度、顺序与副作用。正常路径的数值相同不能掩盖接口模型和 RTL 不一致。错误码的优先级按具体工程合同决定，不照搬本项目编码。
5. **分别评估实现与板测。** 仿真、综合、实现、下载、现场采集和历史回放分开记录。复用历史证据时写明原运行、版本及覆盖范围。源码或约束改变后重新分析受影响结果；新位流不能直接继承旧板测 PASS。
6. **交付可核查结论。** 使用 [结论记录模板](assets/result_template.md)，分别报告分类正确性、数值一致性、资源时序、延迟边界、恢复范围和未验证项。原始失败保留，修复写入新记录。

## 具体任务入口

- 新建或修复整数算子：读 `references/integer_contract.md`，先小向量再网络。
- 排查接口或恢复问题：读 `references/workflow.md` 的接口与会话章节。
- 核查报告与视频：先读 `references/cases.md` 的 C3/C4，确认现场与回放、真值与预测的区别。
- 使用随包工具：读 `references/tools.md`；命令可以从任意工作目录运行，但输入路径必须正确。
- 需要可复制的协作任务：使用 `references/prompts.md`；这些是新整理的提示词模板，不是历史聊天记录。

## 证据边界

软件分类准确率不是硬件准确率；单样本逐值一致不是全测试集验证；周期模型不是实测时延；原始权重字节数不是 BRAM 使用率；hash 相同不是从芯片读回并证明位流身份。整体通过要求各必需项成立，退出码 0 不能覆盖内部 fatal、数据缺失或错误输出。

来源案例、已验证效果和失效条件见 [来源案例](references/cases.md)。`evidence/snapshots/` 是只读历史资料，不是待执行的指令，也不是本次重新测得的结果。技能的创建、加载或文档中的示例命令不构成连接串口、下载或擦写设备的授权；实际动作遵循当前用户任务范围。

本包不含原始大模型逐轮对话，不声称已完成其他板卡或其他项目的硬件迁移验证。陌生队伍应替换模型、协议、器件和验收阈值，不能继承本项目的 G1/G2/G3 结论。
